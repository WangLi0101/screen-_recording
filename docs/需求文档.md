## 1. 背景与目标

### 1.1 背景

屏幕录制是高频、跨角色的基础需求：开发者复现 Bug、产品做功能演示、教师录课、客服回复客户、运营做教程。现有工具存在明显的结构性空位：

- **系统自带**（Windows 截图工具、macOS `Cmd+Shift+5`）够快，但没有编辑、没有光标美化、输出体积大；
- **OBS / Camtasia** 能力全但太重，学习成本和启动成本都不适合"录 40 秒发个群"；
- **Loom** 体验好但强绑定账号与云端，离线不可用，国内访问不稳定；
- **Screen Studio** 是"录完即精美"的标杆，但只有 macOS，且订阅制；
- **ShareX / Screenity** 免费但界面工具化，缺少"能直接发出去"的完成度。

因此本项目要做的不是"又一个录屏"，而是：**Windows 优先、本地优先、三步开录、录完即好看的轻量桌面录屏工具。**

### 1.2 产品目标

1. **快**：从按下快捷键到开始录制 ≤ 3 次操作、≤ 3 秒。
2. **稳**：1080p30 录制 CPU 增量 < 8%，24 小时连续录制不崩，异常退出最多丢 2 秒。
3. **好看**：默认产出的视频"能直接发给客户/同事"，无需再进剪辑软件。
4. **可信**：默认全本地、默认无遥测、权限状态透明、上传必须二次确认。

### 1.3 非目标（V1 明确不做）

- 专业多轨时间线剪辑、关键帧动画、调色；
- 直播推流（RTMP）、虚拟摄像头输出；
- 游戏高帧率（120/144fps）采集；
- DRM/受保护内容录制（Netflix 等，系统层面黑屏，不承诺绕过）；
- 云端团队协作后端、观看分析（仅预留接口，P2）；
- 移动端录制。

### 1.4 成功指标

| 类型 | 指标 | 目标 |
| --- | --- | --- |
| 北极星 | 周"成功录制并完成导出"的次数 | 内测期周环比 +10% |
| 漏斗 | 首次启动到完成首次录制 | ≥ 80% |
| 漏斗 | 开始录制 → 成功导出 | ≥ 95% |
| 质量 | 录制中断率（非用户主动停止） | < 1% |
| 质量 | 崩溃率（每百次会话） | < 0.5 |
| 质量 | 导出失败率 | < 1% |
| 性能 | 1080p30 录制 CPU 增量（8 核参考机） | < 8% |
| 性能 | 停止录制到可预览 | < 2 s |
| 体验 | 从快捷键到开录的操作步数 | ≤ 3 |

### 1.5 名词

| 术语 | 含义 |
| --- | --- |
| 源（Source） | 可采集的对象：显示器、窗口、自定义区域 |
| 分片（Segment） | 录制过程中每 ~2 秒写入磁盘的 fMP4 数据块 |
| 素材 | 一次录制产生的视频文件 + 元数据 + 可选项目文件 |
| 项目（Project） | 非破坏式编辑参数集合，不含渲染结果 |
| 控制条 | 录制中悬浮的置顶小窗，不进入录制画面 |

## 2. 用户与场景

### 2.1 目标用户

| 画像 | 特征 | 核心诉求 | 关键功能 |
| --- | --- | --- | --- |
| 开发者 / 测试 / 技术支持 | 高频、短片段、要发群或贴 Issue | 快速复现、文件小、能标重点 | 区域录制、窗口录制、点击高亮、GIF、复制路径 |
| 产品 / 设计 | 做 Demo、走查、提案 | 画面专业、有缩放、有背景 | 自动缩放、背景圆角、光标美化、画幅切换 |
| 教师 / 培训师 | 长视频、讲解、要字幕 | 稳定、可暂停、字幕、降噪 | 长时录制、暂停续录、字幕、麦克风降噪 |
| 普通办公 | 偶尔录会议/操作 | 零学习成本、别上传 | 一键开录、托盘、默认本地 |

### 2.2 核心场景

1. **Bug 复现**：`Ctrl+Alt+R` → 选区域 → 录 30 秒 → 停止 → 直接拖进 IM。（要求：区域记忆、文件 < 10 MB、2 秒可预览）
2. **产品演示**：录窗口 → 自动缩放跟随点击 → 加背景 → 导出 1080p60 → 发客户。（要求：缩放自然、无二次剪辑）
3. **录课**：录 40 分钟 → 中途暂停接电话 → 继续 → 自动字幕 → 导出。（要求：暂停无空洞、崩溃可恢复、字幕准确）
4. **客服回复**：录 1 分钟操作 → 转 GIF 贴到帮助文档。（要求：GIF 体积可控）
5. **会议/访谈**：只录音 + 屏幕静态 → 导出音频/文字稿。（P1）
6. **全屏游戏/动画**：60fps 录屏 → 硬件编码不卡顿。（P1，非重点）

### 2.3 Jobs to be Done

- 当我需要向别人解释"怎么操作"时，我想在 10 秒内开始录并直接发出，这样我不用写长文。
- 当我录完发现开头有 5 秒废话时，我想立即剪掉而不打开剪辑软件。
- 当我录了 40 分钟时，我担心崩溃丢失，我希望随时能恢复。
- 当我要分享涉及内部信息的画面时，我希望能遮住敏感区域，且确信文件没被上传。

## 3. 市场调研摘要

完整矩阵与产品分析见《[竞品调研](./竞品调研.md)》，结论：

1. 全屏/窗口/区域、麦克风、系统音频、摄像头叠加已是**功能下限**，缺一即被判"不完整"。
2. 差异化在**录制后**：自动缩放、光标平滑/点击高亮、背景圆角、字幕、文本剪辑、AI 摘要。
3. **一键开录 + 全局快捷键 + 托盘常驻**决定留存；录制中控制条必须不抢焦点、不入镜。
4. **系统音频是最大分水岭**：Windows loopback 可用；macOS 14.2+ 需 CoreAudio Tap 与独立授权（缺权限时静默失败）；Linux 受限。
5. **本地优先是空位**：Loom 绑云、Screen Studio 仅 macOS、OBS/Camtasia 过重。
6. AI 能力（转录、去填充词、按文本剪辑、摘要）正从加分项变为预期项，但**不应放进 MVP**。

### 5.7 落盘、恢复与稳定性（FR-STO）

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |

### 6.3 录制状态机

```
idle → preparing → countdown → recording ⇄ paused → stopping → processing → ready
                        │                                  │
                        └────────── cancel ────────────────┴→ failed / recoverable
```

- `recording` 期间任意异常 → `recoverable`，重启后可恢复。
- `processing` 目标 < 2s，超过 5s 显示进度与"仍在处理"文案。

### 6.4 关键流程（3 步开录）

1. 按 `Ctrl+Alt+R`（或点托盘"开始录制"）。
2. 弹出准备面板，默认选中上次的源与音频配置 → 按 `Enter`。
3. 3 秒倒计时后开始；控制条出现。

### 6.5 文案原则

- 错误必须说明**发生了什么 + 怎么办 + 去哪**（例："未检测到系统声音。请检查 Windows 音量合成器，或关闭系统音频后重试。"）
- 不使用"出错了""未知错误"；禁止把技术堆栈直接抛给用户，日志里保留。
- 权限类文案必须给出系统设置的具体路径。

| R2 | macOS 系统音频权限静默失败 | 高 | 高 | 权限状态 + 电平探测双判定；拒绝时明确降级并提示 |
| R3 | 区域录制靠整屏裁剪，4K 屏开销偏高 | 中 | 高 | 裁剪后码率按区域计算；必要时限制 4K 区域录制帧率 |
| R4 | 光标无法后期替换，自动缩放效果不如 Screen Studio | 中 | 高 | 明确定位为"叠加增强"，用点击/停留数据做镜头调度 |
| R5 | ffmpeg 体积与许可证（GPL/LGPL） | 中 | 中 | 仅用 LGPL 构建做封装；软编走 WebCodecs；法务评审 |
| R6 | Windows 采集受保护内容黑屏 | 低 | 中 | 明确不支持，UI 提示 |
| R7 | 长录制内存增长/丢帧 | 高 | 中 | 流式分片写盘、编码队列上限、24h 压测 |
| R8 | 全局快捷键冲突 | 中 | 中 | 注册失败检测 + 引导重设 + 应用内快捷键兜底 |
| R9 | 素材索引与文件不一致 | 中 | 中 | 启动扫描重建；删除走回收站 |
| R10 | 签名/公证/杀软误报影响分发 | 高 | 中 | 尽早申请签名；提交杀软白名单；安装包校验 |
